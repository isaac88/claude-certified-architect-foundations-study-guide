### Claude review

Not mergeable as-is: the harness never retries transients before the model sees them (api.md rule 4 violated), the tool-payload schema diverges from the api.md contract (no isError/errorCategory/isRetryable fields), the case-facts check is a tautology that can never detect a regression, and a regex defect in _json_from_text can silently fail to strip code fences and crash the pipeline.

| Severity | Status | Location | Rule | Change |
|---|---|---|---|---|
| blocker | new | `practice/exercise-4-research-pipeline/pipeline.py:243` | api.md — Only the harness retries transients, with backoff, before the model sees the failure | SimulatedTimeout is caught in search_spoke and immediately converted to a tool result with is_error=True that the coordinator sees on the same turn. No harness-level backoff or retry attempt is made first. The model is required to decide to retry via the alternatives list, which inverts the stated architecture: the harness should absorb the transient invisibly, not delegate recovery to the model. |
| blocker | new | `practice/exercise-4-research-pipeline/pipeline.py:346` | api.md — Tool returns {isError, errorCategory (transient|validation|business|permission), isRetryable, message, attempted}; harness sets is_error from isError | The harness sets is_error from payload["status"] == "error" (a string comparison), not from a payload["isError"] boolean field. The spoke payloads use {status, error:{...}} — the errorCategory, isRetryable, and message fields mandated by the rule are never present. Without errorCategory the harness cannot distinguish transient from validation/business/permission errors, making the retry-before-model rule unimplementable. |
| major | new | `practice/exercise-4-research-pipeline/pipeline.py:178` | Correctness — regex anchors require re.MULTILINE for fence stripping | re.sub(r"^```(?:json)?\s*|\s*```$", "", text) uses ^ and $ without re.M. The substitution works only when the fenced block begins at position 0 with no preamble text. If the extraction spoke's response contains any text before the opening fence (a common LLM behaviour despite "Return ONLY JSON" in the prompt), the opening anchor does not match, the backtick characters are left in the string, and json.loads raises JSONDecodeError, crashing the pipeline. |
| major | new | `practice/exercise-4-research-pipeline/pipeline.py:312` | api.md — Case-facts block injected verbatim on every request and never summarised | The check increments requests_with_case_facts by testing if case_facts_block() in system inside the coordinator loop. system is set once before the loop by embedding case_facts_block() into it, so the substring test is permanently True on every turn regardless of whether the injection logic is working. The resulting assertion (requests_with_case_facts == coordinator_requests) is a tautology and will never fail even if case facts are accidentally removed from the system prompt. |
| major | new | `practice/exercise-4-research-pipeline/fixtures.py:213` | Fixture contract — first journal call always raises SimulatedTimeout (transient) | The first-call transient guard is if _journal_calls == 1 and hits. When the first journal query matches 0 corpus entries, hits is [] and the condition is False, so no SimulatedTimeout is raised. The spoke returns status="empty"; the coordinator treats this as a definitive empty result and will not retry, silently bypassing the transient-recovery path that the exercise is designed to exercise. |
| major | new | `practice/exercise-4-research-pipeline/pipeline.py:379` | Check 2 correctness — timeout must not end the job | timeout_turns filters trace entries where "error" appears in after_status. Check 2 asserts all(t["action"] != ["end_turn"] for t in timeout_turns) — this only verifies that the timeout turn itself dispatched a tool call, not that the coordinator continued on subsequent turns. A coordinator that makes one retry call (satisfying check 2) and then emits end_turn two turns later — without completing the job — would still pass. |
| major | new | `practice/exercise-4-research-pipeline/pipeline.py:290` | api.md — Trim tool payloads before appending to history; keep full payload in harness or manifest | synthesis_spoke builds a payload with {id, claim, url, title, excerpt, date} for every finding and passes it as the user message content of a fresh messages.create call. While the coordinator's ongoing history is correctly trimmed to {id, claim, date}, the synthesis spoke's own messages carry the full mappings that the rule says should stay in the harness/manifest. Check 6 only inspects coordinator_messages and would not catch leakage through the synthesis path. |
| minor | new | `practice/exercise-4-research-pipeline/fixtures.py:211` | Fixture determinism — _journal_calls must be reset between Pipeline instantiations | _journal_calls is a module-level global. fixtures.reset() is defined but never imported or called in pipeline.py. If Pipeline().run() is called more than once in the same process (e.g., in tests), the second run starts with _journal_calls > 0, so the first-call transient fires on the second journal call of the second run rather than the first, silently changing fixture behaviour between runs. |
| minor | new | `practice/exercise-4-research-pipeline/pipeline.py:334` | Anthropic SDK contract — messages list must contain plain dicts or consistently typed SDK objects | messages.append({"role": "assistant", "content": response.content}) stores SDK content-block objects, not plain dicts. The checks() serialisation handles this via model_dump(), but passing a message list that mixes raw dicts (the initial user turn) with SDK typed objects (assistant turns) to subsequent messages.create calls is fragile: SDK versions that validate message types strictly may raise a serialisation error on the second and later coordinator turns. |
| minor | new | `practice/exercise-4-research-pipeline/fixtures.py:196` | Defensive programming — unhandled KeyError crosses tool boundary | pool = {"web": WEB, "journal": JOURNAL}[corpus] raises KeyError for any corpus value not exactly matching those two strings. search_spoke catches only SimulatedTimeout, so a KeyError (e.g., corpus="Web" from a model that ignores the enum) propagates uncaught and crashes the entire run() loop. The tool schema enum prevents this in normal operation but the Python code does not enforce it defensively. |
