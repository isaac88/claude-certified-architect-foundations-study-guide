# 4.6 Multi-instance and multi-pass review

## Self-review is weak

Same session (or same instance with the generator’s chain-of-thought) **retains why it cheated**. It will not prosecute itself. Subtle bugs survive.

**Independent instance**: diff (or files) in, **no** generation reasoning. Catches more.

Extended thinking in the **same** session is not a substitute. Triple self-review with majority vote **hides** intermittent catches (Domain 1.6 / sample Q12 family).

## Multi-pass (attention dilution)

One pass over 14 files → patchy depth, contradictory nits.

1. **Per-file local** passes — consistent depth  
2. **Cross-file integration** pass — data flow, interface mismatch  

Same split as 1.6 prompt chaining. Bigger context window does not restore attention.

## Confidence-based routing

Model **self-reports confidence per finding**. Route **low-confidence** to humans.

Calibrate thresholds on a **labelled validation set** — not a guessed 70%. Aggregate 97% accuracy can hide a rotten document type (Domain 5.5). Stratify before you auto-merge “high confidence”.

Self-reported confidence is a **routing** signal after calibration. It is **not** an escalation policy for support (5.2) and **not** a replacement for explicit criteria (4.1).

## Practice

Generator session writes a module, then “reviews” it and misses its own off-by-one.

**Fix:** new session / new instance, code only, explicit criteria (4.1) + few-shot (4.2) if needed.

14-file PR, inconsistent comments.

**Fix:** per-file + integration pass, not a larger window.

2. When is self-reported confidence legitimate, and when is it a trap?
