# 1.3 Subagent invocation and context passing

## The Task tool

The coordinator spawns subagents with the **Task** tool (also called the Agent tool in some SDK versions; the exam language is Task).

If the coordinator’s `allowedTools` does **not** include `"Task"`, it cannot spawn subagents at all. That is a configuration bug, not a prompting bug.

Each subagent has an **AgentDefinition**: description (so the coordinator knows when to use it), system prompt, and tool restrictions.

Give each subagent only the tools for its job. Synthesis gets a scoped `verify_fact` tool, not the web-search agent’s entire toolkit.

## Context passing

Because of isolation (1.2):

- Include complete findings from prior agents **in the subagent prompt**. Example: pass web search hits and document extracts into synthesis.
- Use **structured** payloads that separate content from metadata (URLs, document names, page numbers). That is how attribution survives across agents.
- Coordinator prompts specify **goals and quality criteria**, not step-by-step procedures. Procedures freeze adaptability; criteria let the spoke choose tactics.

Unstructured prose blobs lose sources. The exam will show a synthesis report with uncited claims while search and document agents “work correctly”. Root cause: context passing dropped metadata. Fix: require claim–source mappings (and keep them structured all the way through).

## Parallel spawning

Emit **multiple Task tool calls in a single coordinator response** to spawn spokes in parallel. That is faster than one Task per turn.

The exam tests latency awareness. Independent subtopics → one turn, many Tasks.

## `fork_session`

Creates independent branches from a **shared analysis baseline**.

Use when you have already paid for a codebase analysis (or similar) and now want to compare two strategies. Each fork diverges after the branch point; neither contaminates the other.

Do not re-run the baseline twice. That is the distractor.

## Practice scenario

Synthesis produces a report with several claims and no source attribution. Web search and document analysis both returned URLs and page numbers.

**Root cause:** those metadata fields never made it into the synthesis prompt (or were flattened into unattributed prose).

**Fix:** require spokes to emit structured claim–source mappings; the coordinator copies that structure into the synthesis prompt; synthesis may only state a claim that has a mapping.

## Check questions

1. The coordinator’s prompt is excellent, but it never spawns subagents. What do you check first?
2. When is `fork_session` the right answer rather than two separate sessions from scratch?
