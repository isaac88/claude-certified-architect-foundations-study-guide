# 1.2 Multi-agent orchestration

When one agent’s tool set or context window cannot cover the job, you add specialists. The exam’s default shape is **hub-and-spoke**.

## Hub-and-spoke

```
                 ┌─────────────┐
                 │ Coordinator │
                 └──────┬──────┘
           ┌────────────┼────────────┐
           ▼            ▼            ▼
      Web search   Doc analysis   Synthesis
```

- The **coordinator** sits at the centre.
- **Subagents** are spokes for specialised tasks.
- **All communication flows through the coordinator.** Subagents never talk to each other.
- The coordinator: decomposes the task, chooses which spokes to invoke, passes context, aggregates results, handles errors, and routes information between them.

Do not always run the full pipeline. A query that is only a document question should not also fire web search.

## Isolation (the most missed idea in this domain)

- Subagents do **not** inherit the coordinator’s conversation history.
- Subagents do **not** share memory between invocations.
- Every fact a subagent needs must be **explicitly** in its prompt.

If the synthesis agent never saw the URLs, the report will have uncited claims. That is not a synthesis bug. That is a context-passing bug (1.3).

## Coordinator responsibilities

1. Analyse the query and **dynamically** select subagents.
2. Partition scope so spokes do not duplicate work (distinct subtopics or source types).
3. Iterative refinement: evaluate synthesis for gaps, re-delegate with targeted queries, repeat until coverage is enough.
4. Route everything through the hub for observability and consistent error handling.

## Narrow decomposition failure

Classic exam pattern: a report on “impact of AI on creative industries” that only covers visual arts. Music, writing, and film are missing. Every subagent completed successfully.

**Root cause:** the coordinator decomposed “creative industries” into visual-arts subtopics only. Downstream agents did their jobs on a bad brief.

Trace failures to their origin. Do not blame the context window, search bias, or the report template unless the stem gives evidence.

## Practice scenario

A multi-agent research system reports on “renewable energy technologies” but only covers solar and wind. Geothermal, tidal, biomass, and fusion are absent. All subagents returned success.

Which component failed?

- A) Web search subagent (biased queries)
- B) Synthesis subagent (dropped sections)
- C) **Coordinator task decomposition** (only solar and wind were assigned)
- D) Report template (no slots for other sources)

**Answer: C.** Same pattern as the creative-industries item. If every spoke succeeded and they all researched the same narrow slice, the brief was wrong.

## Check questions

1. Why must subagents not call each other directly?
2. A coordinator always invokes search, then documents, then synthesis, even for “summarise this attached PDF”. What did the designer get wrong?

## Connects to 1.3

Isolation is the rule. 1.3 is the mechanism: the `Task` tool, what you put in the prompt, parallel spawn, and `fork_session`.
