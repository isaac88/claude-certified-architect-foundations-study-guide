# 3.3 Path-specific rules

`.claude/rules/` files with YAML frontmatter load **only** when the files you are editing match the glob.

```yaml
---
paths:
  - "terraform/**/*"
  - "**/*.test.tsx"
---
# Test / Terraform conventions here
```

## Why not directory-level CLAUDE.md?

Directory `frontend/CLAUDE.md` applies to **that folder**. Test files co-located next to source in **50 directories** will not see a single `tests/CLAUDE.md`.

| Approach | Failure mode |
|---|---|
| **Path-specific glob** | Correct: `**/*.test.tsx` hits every test file, anywhere |
| CLAUDE.md in every directory | 50 copies; drift; missed folders |
| Single root CLAUDE.md with a “tests” heading | Always loaded; burns tokens on every non-test edit |
| A skill | On-demand; people forget; not automatic on test edits |

## Token efficiency

Path-scoped rules are **absent** from context until you touch a matching file. That is the point versus always-on CLAUDE.md.

Use directory CLAUDE.md when conventions are truly **package-shaped** (`services/billing/` has a different domain language). Use globs when conventions follow **file type** across the tree.

## Practice scenario

Tests sit beside source in 50+ directories. Every test must follow the same conventions.

**A)** `.claude/rules/` with `paths: ["**/*.test.*"]` (or language-specific globs)  
**B)** `CLAUDE.md` in every directory  
**C)** One root CLAUDE.md, always loaded  
**D)** A `/test-conventions` skill

**Answer: A.** Automatic, complete coverage, tokens only when editing tests. B does not scale. C wastes context. D is not always-on.
