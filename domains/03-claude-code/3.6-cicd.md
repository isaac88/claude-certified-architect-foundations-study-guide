# 3.6 CI/CD integration

## `-p` / `--print` (memorise)

Runs Claude Code **non-interactive** (print mode). Without it, CI **hangs waiting for a TTY**. This is sample-exam Q10. If the stem is “job hangs, waiting for input”, the answer is `-p`.

Wrong answers:

- Pipe a canned script to stdin (not the supported interface)
- Kill/restart on a 30s timeout (does not fix root cause)
- `--auto-accept` only (permissions, not headless mode)

## Structured output

`--output-format json` plus `--json-schema` → machine-parseable findings. The pipeline posts **inline PR comments**. Regex on free text is the Domain 4 trap in CI clothing.

## Session isolation

The session that **generated** the code is bad at reviewing it. It still holds the reasoning that justified the shortcut. Use an **independent** Claude Code invocation/session for review (Domain 4.6, same idea).

## Incremental reviews

On the second CI run, **include prior findings** and say: report **only new or still-unaddressed** issues. Duplicate nits destroy trust in the bot.

## CLAUDE.md in CI

CI Claude still reads project CLAUDE.md. Put **testing standards, valuable criteria, and fixtures** there. Without that, generated tests are empty boilerplate. User-level `~/.claude/CLAUDE.md` is **not** on the CI machine (3.1 again).

## Practice scenario

Script: `claude "Analyze this PR"` hangs. Logs: waiting for input.

**A)** `-p` (and typically `--output-format json`)  
**B)** Pipe yes/no to stdin  
**C)** Restart after 30s of silence  
**D)** `--auto-accept` without `-p`

**Answer: A.** Headless mode is the designed fix.
