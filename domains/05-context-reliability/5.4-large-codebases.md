# 5.4 Large codebase exploration

## Context degradation

Long sessions stop citing `PaymentProcessor.charge()` and start saying “typical payment patterns”. Verbose Grep/Read output **pushed the real findings out**.

## Mitigations (use together)

| Tool | Job |
|---|---|
| **Scratchpad file** | Durable key findings on disk; later questions read the file, not a 80k-token transcript |
| **Subagent delegation** | Bounded investigations; parent keeps coordination (1.2, 3.4 Explore) |
| **Summary injection** | Compress phase N before spawning phase N+1 spokes |
| **`/compact`** | When the window is full of discovery junk — **after** gold dust is in the scratchpad / case facts |

Do not compact first and hope IDs survive (5.1).

## Crash recovery

Each agent writes **structured state** to a known **manifest** path. On resume, the coordinator **loads the manifest and injects** it into prompts. RAM-only history dies with the process. Ties to 1.7 (fresh start + summary vs stale resume).

## Practice

Overnight exploration of a 2M-line repo; answers get vaguer.

**Best:** scratchpad + scoped subagents + compact as needed + manifest for crashes.  
**Worst:** keep every Grep in the parent “so nothing is lost”.

## Check questions

1. Order of operations: compact, or write the scratchpad?
2. Why summarise **before** spawning the next wave of subagents?

## Connects to 5.5

A confident “typical pattern” is not a calibrated accuracy number. Extraction pipelines have the same overconfidence problem with prettier metrics.
