# 2.3 Tool distribution and `tool_choice`

## Tool overload

Give one agent 18 tools and selection collapses. Descriptions cannot save a haystack.

**Target: 4–5 tools per agent, scoped to the role.**

- Synthesis must not hold web-search tools.
- Web search must not hold document-analysis tools.
- Developer agent: Read, Edit, Grep, Glob — not eighteen MCP wrappers plus Bash for everything.

Distractors when the stem says “18 tools, keeps picking wrong”: lengthen descriptions, bigger model, fine-tune. **Split across specialists** (Domain 1.2). Descriptions are the first fix for *two similar* tools (2.1), not for *eighteen unrelated* tools.

## `tool_choice`

| Value | Behaviour | Use |
|---|---|---|
| `"auto"` | May call a tool or just talk | Default general operation |
| `"any"` | **Must** call a tool; model picks which | Guaranteed structured output when several schemas exist (Domain 4 overlap) |
| `{"type": "tool", "name": "extract_metadata"}` | **Must** call that named tool | Mandatory first step (identity, metadata) before enrichment |

Forced named `tool_choice` is a **programmatic first step**. It complements 1.4 gates: one *requires* a call, the other *blocks* a later call. For refunds you still want a gate, not only hope that `auto` picks `get_customer`.

## Scoped cross-role tools (exam Q9 pattern)

High-frequency **simple** operations should not round-trip the coordinator.

Production: synthesis needs to check a date. Today it returns to the coordinator, which re-delegates to web search: **2–3 extra turns, ~40% latency**. 85% of checks are simple lookups.

| Option | Why not |
|---|---|
| Always bounce via coordinator | Correct for *complex* verification; wrong default |
| Give synthesis the **full** search toolkit | Violates scoping; it will search instead of synthesise |
| Trust research spokes to pre-verify every claim | Claims appear during synthesis; pre-verification cannot see them |
| **Give synthesis a scoped `verify_fact`** | Simple lookups in-place; hard cases still go to the hub |

Constrained alternative to a generic weapon:

- Not `fetch_url` (anything on the internet).
- Yes `load_document` (allow-listed document URLs only).

Same idea as splitting `analyze_document` in 2.1.

## Practice scenario

Synthesis returns to the coordinator for almost every fact check. 85% are simple lookups. Latency +40%.

**A)** Keep hub-only verification; add parallel search spokes.  
**B)** Give synthesis all web-search tools.  
**C)** Require research agents to pre-verify every sentence.  
**D)** Add a scoped `verify_fact` tool on synthesis; complex cases still route through the coordinator.

**Answer: D.** Proportionate. Matches Q9. A does not cut the 85%. B over-scopes. C cannot see claims born in synthesis.
